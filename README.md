# Исследование методов сжатия текстовых сообщений в условиях ЧС (НИР)

![Status](https://img.shields.io/badge/status-stable%20v1.0.0-green)
![Python](https://img.shields.io/badge/python-3.12%2B-blue)
![License](https://img.shields.io/badge/license-MIT-green)

Репозиторий содержит исходный код, данные и научные материалы научно-исследовательской работы (НИР) по теме: 
**«Исследование методов оптимизации размерности латентно-семантического пространства в задачах обработки текстовых сообщений в условиях чрезвычайных ситуаций»**.

---

## 📌 О проекте (Что это и зачем?)

В условиях чрезвычайных ситуаций (ЧС) и в туризме часто возникает необходимость передачи текстовых сообщений (SOS, запросы помощи) по узкополосным каналам связи (спутниковые мессенджеры, рации, слабый интернет). Передача полного текста может быть невозможна или слишком медленной. 

**Цель исследования:** Создание сверхлегкой и высокоточной модели машинного обучения для классификации коротких сообщений (по интентам и уровням срочности), пригодной для развертывания на edge-устройствах (мобильных терминалах спасателей).

**Ключевой научный результат:** Изначальная гипотеза о том, что латентно-семантический анализ (LSA / TruncatedSVD) обеспечит оптимальное сжатие без потери качества, была **эмпирически опровергнута**. Доказано, что для коротких текстов (3–25 слов) разреженная TF-IDF матрица без SVD превосходит LSA по всем параметрам (качество, размер, скорость). Финальная модель весит всего **75.8 КБ** и достигает **Macro F1 = 0.579**, работая на пределе архитектурных возможностей «мешка слов».

---

## 📊 Финальные результаты (v1.0.0)

Оценка проводилась с помощью честной 5-кратной кросс-валидации (`StratifiedGroupKFold` с группировкой по `case_id`, исключающей утечку перефразов).

| Архитектура | Macro F1 (Intent) | CWR (Безопасность) | Размер модели | Время обучения |
| :--- | :--- | :--- | :--- | :--- |
| **TF-IDF без SVD (Final)** | **0.579** | **0.628** | **75.8 КБ** | **0.85 сек** |
| LSA (TruncatedSVD, k=73) | 0.483 | 0.556 | 299.1 КБ | 2.24 сек |

*   **Urgency Acc on Correct Intent:** 0.678
*   **Архитектурный предел (Train=Test):** 0.599 (модель находится на расстоянии 2 п.п. от теоретического максимума для Bag-of-Words).

## 📂 Структура репозитория
*   `data/` — финальный датасет (`corpus_preprocessed.csv`), словари (`keep_words.txt`, пустой `stop_words.txt`) и финальные параметры (`best_min_df.txt`).
*   `src/` — основной пайплайн (от чтения данных до финальной валидации).

*   `models/` — сохраненные обученные модели (векторизатор).

*   `start.bat` — скрипт для автоматического запуска пайплайна.

## 🛠 Дополнительные инструменты (`tools/`)

В папке `tools/` собраны скрипты, которые использовались в ходе исследования для аудита, тестирования гипотез и ручной работы с данными.

### 1. `balance_check.py` (Аудит дисбаланса корпуса)
*   **Что делает:** Анализирует `corpus.csv` и выводит статистику по классам (интентам) с разбивкой на реальные и синтетические данные. 
*   **Что говорит:** Показывает самый частый и самый редкий класс, разницу между ними, а также проверяет соблюдение безопасного соотношения реальных данных к синтетике (3:1).
*   **Зачем нужен:** Перед запуском обучения позволяет понять, не перевесит ли один класс все остальные, и достаточно ли данных для миноритарных классов (например, `погибший`).

### 2. `edit_corpus.py` (Интерактивный редактор корпуса)
*   **Что делает:** Консольный редактор (v3.4). Позволяет фильтровать сообщения по категории, интенту, срочности или источнику (реал/синтетика). Умеет массово менять интенты, срочность, переключать флаг синтетики и удалять мусорные строки. Автоматически создает бэкапы `corpus.csv` перед сохранением.
*   **Что говорит:** Выводит превью отредактированных строк и пишет лог изменений.
*   **Зачем нужен:** Основной инструмент для ручной переразметки, чистки датасета и исправления ошибок LLM при генерации синтетики.

### 3. `grid_search_k.py` (Поиск оптимального k*)
*   **Что делает:** Выполняет Grid Search по количеству компонент SVD (`k`) на честной кросс-валидации. Строит график зависимости `F1_intent` и `CWR` от `k`.
*   **Что говорит:** Выводит таблицу с метриками для каждого `k` и сохраняет график. Позволяет увидеть "плато", после которого рост размерности не дает прироста качества.
*   **Зачем нужен:** Использовался на этапе исследования LSA для доказательства того, что после `k=73` модель начинает улавливать только математический шум (дисперсия осей падает ниже 0.24%).

### 4. `interpret_axes.py` (Семантический аудит латентных осей)
*   **Что делает:** Обучает SVD на текущем словаре и извлекает топ-10 слов для каждой латентной оси. Сохраняет результат в `.txt` и генерирует `.json` с промптами для LLM.
*   **Что говорит:** Показывает, какие слова сгруппировались вокруг каждой оси (например, ось «лавина, снег, укрытие»). Позволяет увидеть «слепые зоны» — концепты, для которых модель не смогла выделить отдельную ось.
*   **Зачем нужен:** Использовался для подтверждения того, что LSA выучила реальные семантические связи, а не просто частотные паттерны. Именно с его помощью было доказано, что LSA не формирует якорь для `запроса_маршрута`.

### 5. `overfit_check.py` (Стресс-тест «Потолок»)
*   **Что делает:** Обучает модель на 100% данных и тестирует на этих же данных (Train = Test).
*   **Что говорит:** Показывает теоретический предел запоминания архитектуры. Выводит `F1_intent` и `Accuracy`.
*   **Зачем нужен:** Ключевой инструмент для доказательства оптимальности. Если честный F1 (0.579) почти равен Train=Test (0.599), значит модель не переобучена, и мы выжали из неё максимум.

### 6. `synthetic_test.py` (Тест на смешанных данных)
*   **Что делает:** Обучает модель на смеси реальных и синтетических данных, а затем тестирует на отложенной выборке, куда тоже попадает синтетика.
*   **Что говорит:** Показывает, насколько сильно модель переобучается на шаблоны LLM. Если F1 на смешанном тесте сильно выше честного F1, значит, генерация однотипна.
*   **Зачем нужен:** Использовался для обоснования отказа от дальнейшей генерации синтетики в классах с высокой долей шаблонности (например, `запрос_погоды`).

## 📈 Как читать результаты (Интерпретация графиков)

После запуска `08_validation.py` в папке `plots/validation/` появляются три ключевых графика:
1.  **Матрица ошибок (Intent):** Показывает, какие классы модель путает (например, «эффект магнита» у `природной_угрозы`).
2.  **Матрица ошибок (Urgency):** Показывает, что 95% ошибок — это смежные градации (3↔4), а не дальние (1↔4).
3.  **F1 по классам с 95% CI:** Показывает, каким классам можно доверять (`проверка_связи`), а какие статистически нестабильны из-за малого числа примеров (`запрос_маршрута`).


В папке `plots/comparison/` находится главный график НИР — **Сравнение LSA и TF-IDF** (визуальное доказательство того, что TF-IDF одновременно точнее, легче и быстрее).
