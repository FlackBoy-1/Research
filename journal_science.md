# Научный отчёт по НИР
**Тема:** Исследование методов оптимизации размерности латентно-семантического пространства в задачах обработки текстовых сообщений в условиях чрезвычайных ситуаций.

---

# Аннотация

**Актуальность.** В условиях чрезвычайных ситуаций (ЧС) автоматическая обработка коротких текстовых сообщений (SMS, радиограмм) на edge-устройствах требует моделей, способных к сильному сжатию данных при сохранении семантической адекватности. Классическим подходом к такому сжатию является латентно-семантический анализ (LSA), однако его применимость к коротким текстам остается дискуссионной.

**Цель работы.** Разработка метода оптимизации размерности текстовых сообщений для задач ЧС и поиск архитектуры классификатора, обеспечивающей максимальное сжатие без потери качества.

**Методология.** Исследование проведено на авторском корпусе из 2616 сообщений (16 классов интентов, 4 уровня срочности). Для предотвращения утечки данных использовалась кросс-валидация с жесткой группировкой по сценариям (StratifiedGroupKFold, `case_id`) и изоляция синтетических данных. Изначально сжатие планировалось осуществить через LSA (TF-IDF + TruncatedSVD), однако в ходе работы было проведено сравнительное исследование с разреженной TF-IDF без сингулярного разложения. Также применена авторская методика ценностно-ориентированной балансировки классов на основе прикладной метрики Cost-Weighted Recall (CWR).

**Результаты.** Цель по сжатию достигнута: финальная модель занимает всего 75.8 КБ и демонстрирует честный Macro F1 = 0.579, CWR = 0.628 и точность определения срочности 0.678. При этом гипотеза о преимуществе LSA как метода сжатия **опровергнута**. Установлено, что для коротких сообщений LSA не только уступает по качеству (Macro F1 = 0.483 против 0.579), но и проигрывает в вычислительной эффективности, занимая в 4 раза больше памяти (299 КБ) из-за плотности матриц SVD.

**Научная и практическая значимость.** Эмпирически доказана нецелесообразность применения классического LSA для коротких текстов. Выявлена критическая роль синтаксиса (предлогов) в задачах распознавания запросов. Полученный сверхлегкий классификатор пригоден для развертывания на устройствах с ограниченными ресурсами, а результаты исследования задают вектор для перехода к контекстным эмбеддингам (RuBERT).

## 1. Введение

### 1.1. Актуальность и постановка проблемы
В условиях чрезвычайных ситуаций (ЧС) оперативный обмен информацией часто происходит посредством коротких текстовых сообщений (SMS, сообщения в мессенджерах, радиограммы). Такие сообщения имеют жесткие ограничения по длине (от 3 до 25 слов), содержат специфическую лексику и зачастую передаются по каналам с низкой пропускной способностью. Для автоматической маршрутизации и оценки критичности (срочности) таких сообщений на edge-устройствах (мобильных терминалах спасателей) требуются сверхлегкие и высокоточные модели машинного обучения.

Классическим подходом к снижению размерности текстовых признаков является латентно-семантический анализ (LSA), основанный на усеченном сингулярном разложении (TruncatedSVD) матрицы TF-IDF. Теоретически LSA позволяет отбросить шумовые компоненты и сжать модель. Однако для коротких текстов возникает **фундаментальное противоречие**: с одной стороны, сжатие размерности должно снизить вычислительную сложность; с другой стороны, короткие тексты не обладают достаточным контекстом для формирования устойчивых латентных связей, что может привести к деградации качества и, парадоксальным образом, к увеличению физического размера модели.

### 1.2. Основная гипотеза (H1) и её эволюция в ходе исследования
> **Изначальная гипотеза (H1):** Для корпуса коротких сообщений в домене ЧС существует такое количество латентных компонент (`k*`) и объем словаря (`V*`), при которых LSA-модель (TF-IDF + TruncatedSVD) обеспечивает достаточное сжатие данных (уменьшение размера модели) без существенной потери качества классификации (допуск ≤ 2 п.п. относительно полной модели).

**Уточнение по итогам исследования.** В процессе работы было доказано, что цель по сжатию данных (созданию сверхлегкой модели) достижима, но **не тем инструментом, который планировался изначально**. LSA не обеспечивает преимуществ для коротких текстов. Поэтому итоговая гипотеза (H1_final) формулируется так:

> **Итоговая гипотеза (H1_final):** Для коротких сообщений в домене ЧС семантическая адекватность может быть сохранена при существенном сжатии модели (до 75 КБ), однако эффективным методом такого сжатия является не LSA, а строгая фильтрация словаря (min_df) на разреженной TF-IDF матрице, которая одновременно превосходит LSA по качеству и вычислительной эффективности.

Таким образом, **основная цель НИР (создание сверхлегкого классификатора) достигнута**, а гипотеза о способе её достижения (через LSA) была скорректирована на основе эмпирических данных.

### 1.3. Научно значимые вторичные гипотезы
В ходе исследования были выдвинуты вторичные гипотезы, представляющие интерес для широкого круга задач обработки естественного языка (NLP) и машинного обучения (ML):

*   **H2 (Роль синтаксиса в коротких текстах):** Удаление стоп-слов (предлогов, союзов, местоимений) — стандартная практика предобработки. Однако для коротких сообщений стоп-слова несут критическую синтаксическую нагрузку (например, отличают вопрос «как пройти?» от констатации «я на перевале»). Гипотеза: *отказ от удаления стоп-слов повышает качество классификации интентов, связанных с запросами.*
*   **H3 (Парадокс сжатия размерности):** Усеченное сингулярное разложение (SVD) снижает количество признаков, но генерирует плотные (dense) матрицы компонент. Гипотеза: *при работе с разреженными матрицами TF-IDF физический размер LSA-модели (при сериализации) может оказаться больше, чем размер полной TF-IDF модели.*
*   **H4 (Валидация на перефразах):** Игнорирование группировки данных по смыслу (перефразирования) при кросс-валидации приводит к утечке данных (Data Leakage). Гипотеза: *использование группировки по `case_id` (StratifiedGroupKFold) статистически значимо снижает метрики по сравнению с наивным сплитом, но отражает реальную обобщающую способность.*
*   **H5 (Ценностно-ориентированная балансировка):** Стандартная математическая балансировка классов (`class_weight='balanced'`) выравнивает классы независимо от их прикладной ценности. Гипотеза: *для задач с разной ценой ошибки (Cost-Sensitive Learning) использование гибридных весов (частота класса × вес прикладной ошибки CWR) с кусочно-линейным сглаживанием повышает прикладные метрики безопасности без коллапса редких классов.*
*   **H6 (Пределы защиты редких слов):** Принудительное сохранение редких доменных слов (`keep_words`) в словаре обходит фильтр `min_df`. Гипотеза: *защита редких слов эффективна для моделей на полном словаре, но не спасает латентное пространство LSA, если слова не имеют контекстной поддержки (совместной встречаемости) в корпусе.*

## 2. Архитектура вычислительного пайплайна и математический аппарат

Для обеспечения воспроизводимости результатов и прозрачности методологии исследование реализовано в виде последовательного вычислительного пайплайна, состоящего из 9 модулей. Ниже описано, какие математические и алгоритмические операции выполняет каждый шаг.

### 2.1. Шаг 1: Валидация и чтение корпуса (`01_read_corpus.py`)
Осуществляется загрузка исходного датасета, проверка типов данных, отсутствия пропусков (NaN) и целостности идентификаторов сценариев (`case_id`). 

### 2.2. Шаг 2: Предобработка и лемматизация (`02_preprocess.py`)
Выполняется приведение текста к нижнему регистру и очистка от шумовых символов. Ключевые операции:
1.  **Регулярные выражения (RegEx):** Числовые координаты (широта, долгота) заменяются на универсальный токен `[coord]` (регулярное выражение `\b\d{1,3}[.,]\d{3,}\b`). Аббревиатура SOS безусловно заменяется на `[sos]`.
2.  **Лемматизация:** Слова приводятся к начальной форме (лемме) с помощью морфологического анализатора `pymorphy3`. Это снижает размерность словаря за счет объединения словоформ (например, «лавиной», «лавины» → «лавина»).

### 2.3. Шаг 3: Векторизация и отбор признаков (`03_lsa.py`, `06_find_v.py`)
Тексты переводятся в числовой вид с помощью модели **TF-IDF** (Term Frequency — Inverse Document Frequency) с использованием униграмм и биграмм.
Математически вес терма \(t\) в документе \(d\) вычисляется как:
\[
TFIDF(t, d) = TF(t, d) \times IDF(t)
\]
где \(TF(t, d)\) — частота терма в документе (в данной реализации — нормированная), а \(IDF(t) = \ln\left(\frac{1 + N}{1 + DF(t)}\right) + 1\), где \(N\) — общее число документов, а \(DF(t)\) — количество документов, содержащих терм \(t\) (Document Frequency).

Для фильтрации шума используется порог `min_df` (в данной реализации — порог по суммарной частоте терма в корпусе). Слова с частотой ниже порога удаляются, если они не входят в список критически важных `keep_words`.

### 2.4. Шаг 4: Поиск гиперпараметров (`04_find_k.py`, `05_select_k.py`)
Для LSA-архитектуры выполняется поиск оптимального количества компонент \(k^*\). Используется **Усеченное сингулярное разложение** (TruncatedSVD). Матрица признаков \(X\) (размером \(m \times n\)) раскладывается как:
\[
X \approx U_k \Sigma_k V_k^T
\]
где \(U_k\) и \(V_k\) — матрицы левых и правых сингулярных векторов, а \(\Sigma_k\) — диагональная матрица с \(k\) наибольшими сингулярными числами. Матрица \(X_k = U_k \Sigma_k\) представляет собой сжатое латентное пространство размерности \(k\). Поиск \(k^*\) осуществляется эмпирически по метрике F1-score с проверкой семантической интерпретируемости осей и объясненной дисперсии.

### 2.5. Шаг 5: Классификация (`08_validation.py`, `09_compare_tfidf_lsa.py`)
В качестве классификатора используется **Логистическая регрессия** (Logistic Regression) с мультиномиальным (Softmax) распределением. Вероятность принадлежности объекта \(x\) к классу \(c\):
\[
P(y=c|x) = \frac{\exp(w_c^T x + b_c)}{\sum_{j=1}^{K} \exp(w_j^T x + b_j)}
\]
где \(w_c\) и \(b_c\) — веса и смещение для класса \(c\), \(K\) — количество классов. Оптимизация весов происходит путем минимизации кросс-энтропии с L2-регуляризацией.

### 2.6. Шаг 6: Ценностно-ориентированная балансировка классов (`08_validation.py`)
Вместо стандартного `class_weight='balanced'` применяется кусочно-линейное масштабирование весов (Piecewise Linear Scaling). Базовый вес класса \(c\) рассчитывается как:
\[
W_{base}(c) = \sqrt{\frac{N_{max}}{N_c}} \times W_{CWR}(c)
\]
где \(N_{max}\) — частота самого многочисленного класса, \(N_c\) — частота класса \(c\), а \(W_{CWR}(c)\) — прикладной вес ошибки (например, для `военная_угроза` = 1.0, для `запрос_маршрута` = 0.1). 
Далее \(W_{base}\) масштабируется через кусочно-линейную функцию для ограничения максимального и минимального влияния на функцию потерь (коридор [0.6, 2.0]).

### 2.7. Шаг 7: Честная кросс-валидация (`08_validation.py`)
Для предотвращения утечки данных (Data Leakage) используется **StratifiedGroupKFold** (5 фолдов). Группировка осуществляется по `case_id`, что гарантирует, что перефразы одного и того же события не попадут одновременно в Train и Test. Синтетические данные не попадают в тестовую выборку. Оценка метрик производится на Out-of-Fold (OOF) предсказаниях, когда каждый объект побывал в тесте ровно один раз.

### 2.8. Шаг 8: Расчет метрик качества
Помимо стандартных метрик (Macro F1, Accuracy), вычисляются прикладные метрики:
*   **Urgency Acc on Correct Intent:** Точность предсказания срочности на подмножестве объектов, где интент был предсказан верно.
*   **Cost-Weighted Recall (CWR):** Взвешенный recall, учитывающий цену пропуска (False Negative) для каждого класса:
\[
CWR = \frac{\sum_{c=1}^{K} W_{CWR}(c) \cdot TP_c}{\sum_{c=1}^{K} W_{CWR}(c) \cdot (TP_c + FN_c)}
\]
*   **Доверительные интервалы:** Для оценки статистической надежности метрик используется бутстрэп (bootstrap) с ресемплингом (500–1000 итераций) для расчета 95% доверительных интервалов (CI).

## 3. Описание корпуса данных и разметки

### 3.1. Структура и объем корпуса
Для обучения и валидации моделей использовался специализированный корпус текстовых сообщений в домене ЧС (спасательные операции, туризм, техногенные и военные угрозы). 
*   **Общий объем:** 2616 строк.
*   **Объем для честной валидации:** 2347 строк. В Out-of-Fold оценку попадают только реальные (не сгенерированные) сообщения, прошедшие фильтрацию по минимальному количеству примеров на класс (не менее 2).
*   **Синтетические данные:** Используются только в Train-выборке. Разделение происходит с учетом `case_id`: если сценарий (кейс) целиком уходит в Test, вся связанная с ним синтетика исключается из Train.

### 3.2. Таксономия интентов (16 классов)
Каждое сообщение размечено одним из 16 классов интентов, сгруппированных по уровням приоритета (от угрозы жизни до запросов):
1.  **Угроза жизни:** `погибший`, `травма`, `природная_угроза` (лавины, камнепады), `техногенная_угроза` (утечки, взрывы), `военная_угроза` (обстрелы, БПЛА), `животная_угроза`.
2.  **Потеря:** `потерялся` (потерян другой человек), `заблудился` (потерял ориентир сам).
3.  **Ресурсы/Связь:** `нет_припасов` (еда, вода), `техническая_неисправность` (сломалось оборудование).
4.  **Констатация:** `погода`, `позиция` (координаты или описание места), `статус_группы` («всё хорошо»).
5.  **Запросы/Тесты:** `проверка_связи`, `запрос_маршрута`, `запрос_информации`.

### 3.3. Шкала срочности (Urgency 1–4)
Для каждой строки определена срочность, коррелирующая с кодами реагирования спасательных служб:
*   `1` (Тест/неважное): проверка связи, плановые статусы.
*   `2` (Важное сообщение): запросы информации, незначительные поломки. Угрозы жизни нет.
*   `3` (Смертельная опасность с запасом): ситуация угрожает жизни, но есть время (часы/сутки) или человек может спастись сам.
*   `4` (Прямая угроза жизни/смерть): спасение возможно только извне, факт смерти.

## 4. Результаты экспериментального исследования

Экспериментальная часть включала сравнение двух архитектур (сжатой LSA и полной TF-IDF) на идентичных фолдах и оценку качества предложенного финального пайплайна.

### 4.1. Доказательство честности и оптимальности финальных метрик

Цифры, полученные в результате валидации, не являются следствием случайного подбора параметров или утечки данных. Путь к финальному результату (F1_intent = 0.579, CWR = 0.628) состоял из трех этапов: обеспечение честности оценки, исчерпывающий поиск гиперпараметров и доказательство архитектурного предела.

#### 4.1.1. Обеспечение честности (Zero Data Leakage)
На ранних этапах исследования метрики завышались из-за утечки данных. Для получения статистически честных результатов были внедрены следующие механизмы:
1.  **Группировка по `case_id`:** Записи, являющиеся перефразами одного и того же события (кейса), имеют одинаковый `case_id`. Разделение на Train и Test производится с жесткой группировкой по этому признаку (StratifiedGroupKFold). Это гарантирует, что модель не сможет «подсмотреть» ответ, увидев почти идентичный текст в обучающей выборке.
2.  **Строгая изоляция синтетики:** Сгенерированные нейросетью данные (LLM) не попадают в тестовую выборку. В Test используются исключительно реальные сообщения.
3.  **Обучение внутри пайплайна:** Векторизатор (TF-IDF) и алгоритм отбора признаков (`min_df`) обучаются исключительно на Train-фолде. Тестовая выборка проходит только через метод `transform`. Это исключает утечку информации о словаре теста.
4.  **Out-of-Fold валидация:** Оценка производится на 5 фолдах, где каждый объект побывал в тесте ровно один раз (агрегация OOF). Это устраняет статистическую случайность одного удачного разбиения.

#### 4.1.2. Доказательство оптимальности гиперпараметров
Мы утверждаем, что найденные параметры близки к оптимальным для данной архитектуры, на основании следующих проведенных экспериментов:
*   **Словарь (`min_df`):** Был проведен перебор от 1 до 20. Порог `min_df=1` (полный словарь) привел к падению CWR до 0.499 из-за шума от опечаток и гапаксов. Порог `min_df=9` (предложенный автоматикой) отсек важные редкие маркеры (CWR=0.508). Значение `min_df=7` показало лучший баланс между очисткой от шума и сохранением доменной лексики (CWR=0.628).
*   **Размерность латентного пространства (`k*`):** Для LSA был проведен Grid Search по `k` от 45 до 130. Анализ семантических осей и объясненной дисперсии показал, что после `k=73` дисперсия падает ниже 0.24%, а новые оси заполняются математическим шумом. Следовательно, `k=73` — это семантический предел для данного корпуса.
*   **Балансировка классов:** Перебор весов (от жесткого `balanced` до полного отключения) показал, что отказ от балансировки приводит к обнулению миноритарных классов (F1 у `запроса_маршрута` падает до 0.00), а чрезмерное занижение весов безопасных классов вызывает «паранойю» модели. Кусочно-линейный градиент [0.6–1.0] признан Парето-оптимальным компромиссом между техническим F1 и прикладной безопасностью CWR.
*   **Предобработка:** Эмпирически доказано, что удаление стоп-слов (предлогов) уничтожает синтаксические маркеры запросов, а сохранение латиницы вносит шум. Финальная конфигурация (пустые стоп-слова, без латиницы) максимизирует качество.

#### 4.1.3. Доказательство архитектурного предела («Потолок»)
Для ответа на вопрос «а можно ли было получить F1 больше?» был проведен **стресс-тест** (Overfitting Check): модель обучалась на всем корпусе (2616 строк) и тестировалась на тех же самых данных (Train = Test). Цель — проверить, способна ли текущая архитектура (TF-IDF + LogisticRegression) хотя бы запомнить данные при отсутствии шума в тесте.

**Результаты стресс-теста (Train = Test):**
*   `F1_intent` (Macro): **0.5990**
*   `Accuracy`: **0.5948**

**Сравнение с честной кросс-валидацией (Out-of-Fold):**
*   Честный `F1_intent` = **0.579**
*   Честный `Accuracy` = **0.596**

**Научный вывод:**
Разрыв между теоретическим пределом запоминания (Train=Test) и честной обобщающей способностью (Out-of-Fold) составляет всего **2 процентных пункта** по F1 и практически равен нулю по Accuracy. 
Это доказывает три важных факта:
1.  **Модель не переобучена.** Нет разрыва между Train и Test, который указывал бы на заучивание шума.
2.  **Потолок 0.60 — это архитектурное ограничение.** Даже имея перед глазами правильные ответы (в режиме Train=Test), линейная модель на основе «мешка слов» (Bag-of-Words) не может разделить 16 классов лучше, чем на 60%. Оставшиеся 40% ошибок — это либо лексически неразрешимые случаи (например, «Я на перевале» и «Как пройти к перевалу»), либо шум в ручной разметке, либо отсутствие контекста отрицаний.
3.  **Пробить этот потолок без смены архитектуры невозможно.** Дальнейшее улучшение качества (F1 > 0.60 и CWR > 0.70) требует перехода к контекстным эмбеддингам (RuBERT), которые способны улавливать порядок слов и синтаксические связи.

### 4.2. Сравнение архитектур: LSA (k=73) vs TF-IDF без SVD
Обе модели обучались в одинаковых условиях: `StratifiedGroupKFold` (5 фолдов с группировкой по `case_id`), TF-IDF с биграммами (`min_df=7`), кастомные веса классов (`custom_smooth` с градиентом 0.6–1.0).

### 4.5. Анализ структуры ошибок
На основе агрегированной матрицы ошибок (Intent) выявлены три системных паттерна:
1.  **Эффект «Магнита» (`природная_угроза`):** Класс имеет F1 = 0.56 и вбирает в себя ошибки из `статус_группы`, `погоды`, `травмы` и `техногенной_угрозы`. Это объясняется семантической широтой концепта «на природе что-то происходит».
2.  **Смешение локаций:** Классы `позиция`, `запрос_маршрута` и `статус_группы` образуют «треугольник» взаимных ошибок. Без явных цифровых координат (или при их отсутствии) модель не всегда отличает «Я на перевале» (позиция) от «Как пройти к перевалу?» (запрос маршрута).
3.  **Ошибки срочности:** Анализ матрицы ошибок по Urgency показывает, что модель практически не ошибается в «дальних» переходах (1 ↔ 4). 95% ошибок — это смежные градации (3 ↔ 4), что отражает субъективность границы между «смертельной опасностью с запасом времени» и «прямой угрозой жизни».

## 5. Обсуждение результатов

Анализ полученных данных позволяет сформулировать три ключевых научных вывода, объясняющих поведение моделей на коротких текстах.

### 5.1. Почему LSA проиграла полной TF-IDF?
Классическая гипотеза о том, что сжатие размерности (LSA) снижает вычислительную сложность, для коротких сообщений не работает. Причины:
1.  **Дефицит контекста:** Сообщения длиной 3–25 слов не дают матрице SVD достаточного контекста для формирования устойчивых латентных связей. Точные лексические маркеры («жгут», «брод», «рация») несут до 80% смысла сообщения, и их сохранение важнее поиска абстрактных связей.
2.  **Парадокс плотных матриц:** Вопреки теории, LSA-модель оказалась в 4 раза тяжелее (299 КБ против 75.8 КБ). Причина в том, что объект `TruncatedSVD` хранит плотную (dense) матрицу компонент `73 × V` типа `float64`. В то же время полная TF-IDF-модель оперирует сильно разреженной (sparse) матрицей весов логистической регрессии, которая отлично сжимается при сериализации (pickle).

### 5.2. Критическая роль синтаксиса в коротких текстах
Эксперименты подтвердили гипотезу H2. Отказ от стандартного удаления стоп-слов (предлогов и союзов) привел к росту F1 для класса `запрос_маршрута` с 0.00 до 0.34. В коротких сообщениях предлоги (`до`, `к`, `от`, `через`) и вопросительные слова (`как`, `где`) выступают главными маркерами вопроса, отличающими запрос («Как пройти к реке?») от констатации («Мы у реки»). Удаление стоп-слов убивает эту синтаксическую структуру.

### 5.3. Эффективность ценностно-ориентированной балансировки
Стандартная балансировка (`class_weight='balanced'`) делает одинаково важными все классы, независимо от их прикладной ценности. Внедрение кусочно-линейного градиента весов на основе метрики CWR позволило достичь сразу двух целей:
1.  Защитить редкие, но критически важные классы (`военная_угроза`, `техногенная_угроза`) от игнорирования моделью.
2.  Не допустить «паранойи», когда модель предсказывает угрозу везде, чтобы не получить штраф (что произошло в Эксперименте А2 при линейном пересчете весов).

## 6. Выводы и заключение

В ходе научно-исследовательской работы была достигнута цель по созданию сверхлегкого и высокоточного классификатора для сообщений в условиях ЧС, а также эмпирически доказана несостоятельность применения LSA для данной задачи.

### 6.1. Статус выдвинутых гипотез

| Гипотеза | Формулировка (кратко) | Статус |
| :--- | :--- | :--- |
| **H1 (изначальная)** | LSA (сжатие) сохраняет качество и снижает сложность по сравнению с TF-IDF | **Опровергнута.** LSA уступает по F1 (на 9.6 п.п.), CWR (на 7.2 п.п.) и в 4 раза тяжелее. |
| **H1_final (итоговая)** | Сжатие текстового пространства для коротких сообщений ЧС возможно без потери смысла | **Подтверждена.** Финальная модель весит 75.8 КБ и сохраняет F1 = 0.579 (на пределе архитектуры). |
| **H2 (Роль синтаксиса)** | Отказ от удаления стоп-слов повышает качество для коротких текстов | **Подтверждена.** Рост F1 для запросов, сохранение синтаксических маркеров. |
| **H3 (Парадокс сжатия)** | SVD-модель может быть физически больше полной TF-IDF из-за плотных матриц | **Подтверждена.** LSA (299 КБ) тяжелее TF-IDF (75.8 КБ) в 4 раза. |
| **H4 (Утечка данных)** | Валидация с группировкой по `case_id` снижает метрики, но отражает честную обобщающую способность | **Подтверждена.** Устранена утечка через перефразы (Data Leakage). |
| **H5 (Балансировка)** | Ценностно-ориентированная балансировка повышает безопасность (CWR) без коллапса классов | **Подтверждена.** Достигнут баланс CWR=0.628 при сохранении F1=0.579. |
| **H6 (Защита слов)** | Защита редких слов (`keep_words`) спасает классы без контекстной поддержки в LSA | **Опровергнута.** Защита слов не помогла LSA найти якоря для `запроса_маршрута`; проблема в архитектуре. |

### 6.2. Ограничения исследования
1.  **Специфика домена:** Модель обучена на русскоязычных сообщениях в домене ЧС (туризм, военные действия, техногенные аварии). Перенос на другие языки или домены потребует переобучения.
2.  **Технический компромисс с синтетикой:** Для класса `проверка_связи` (радиопротокол) флаг синтетических данных был снят, чтобы дать модели достаточный объем примеров. Это осознанное методическое решение, которое может давать слегка оптимистичную оценку для данного конкретного класса.
3.  **Классы с малым support:** Классы `запрос_маршрута` (n=49) и `животная_угроза` (n=75) имеют широкие доверительные интервалы (до ±13 п.п.). Выводы по ним требуют осторожности.

### 6.3. Направления дальнейшей работы
Архитектурный предел линейных моделей (TF-IDF + LogisticRegression) на данном корпусе достигнут. Дальнейшее улучшение качества (F1 > 0.60 и CWR > 0.70) невозможно без перехода к контекстным эмбеддингам.
*   **Поскольку основная цель (сжатие) достигнута на TF-IDF, дальнейшая работа должна быть направлена не на поиск других методов сжатия, а на повышение семантической точности через контекстные эмбеддинги (RuBERT)**
*   **Внедрение RuBERT:** Использование предобученных трансформеров (например, RuBERT-tiny для сохранения компактности) позволит модели учитывать порядок слов и контекст отрицаний («связь есть» vs «связи нет»).
*   **Расширение корпуса:** Целевой сбор реальных сообщений для классов `позиция` и `запрос_маршрута` (сейчас они лексически бедны).
